## ADDED Requirements

### Requirement: Fetch message history
The system SHALL return the full message history for a job via `GET /chat/:jobId/messages`. Response MUST match `docs/api-contract.md §2.5`.

#### Scenario: Successful history fetch
- **WHEN** an authenticated user (CLIENT or HANDYMAN) party to the job calls `GET /chat/:jobId/messages`
- **THEN** the system returns HTTP 200 with an array of messages each containing `id`, `senderId`, `senderName`, `senderRole`, `content`, `isAI`, and `createdAt`

#### Scenario: User not party to the job
- **WHEN** a user not associated with the job calls `GET /chat/:jobId/messages`
- **THEN** the system returns HTTP 403

#### Scenario: Non-existent job
- **WHEN** `GET /chat/:jobId/messages` is called with an invalid `jobId`
- **THEN** the system returns HTTP 404

### Requirement: Send a message via REST
The system SHALL persist a chat message and relay it via WebSocket when `POST /chat/:jobId/messages` is called. Response MUST match `docs/api-contract.md §2.5`.

#### Scenario: Successful message send
- **WHEN** an authenticated user party to the job calls `POST /chat/:jobId/messages` with `{ content: "string" }`
- **THEN** the system returns HTTP 201 with `id`, `senderId`, `content`, `isAI: false`, `createdAt`, and emits `chat:message` to both parties via `/chat` WebSocket namespace

#### Scenario: Empty content rejected
- **WHEN** `POST /chat/:jobId/messages` is called with empty `content`
- **THEN** the system returns HTTP 400

### Requirement: AI-assist message flag
Chat messages generated by the LLM assistant SHALL be stored with `isAI: true` and `senderRole: "AI"`. Human messages SHALL always have `isAI: false`.

#### Scenario: AI-generated message stored correctly
- **WHEN** the `LLMService` generates a response message
- **THEN** the persisted `ChatMessage.isAI` is `true` and `senderRole` is `"AI"` in the response payload

### Requirement: LLM service interface stubbed
The `LLMService` SHALL be implemented behind a TypeScript interface. For MVP, the stub implementation SHALL return a placeholder response. The live implementation is wired when the LLM provider is confirmed.

#### Scenario: Stub returns placeholder when provider not configured
- **WHEN** `LLM_API_KEY` environment variable is absent
- **THEN** `LLMService` stub is injected; no external LLM calls are made, and AI-assist messages are not sent

#### Scenario: Live LLM calls when provider configured
- **WHEN** `LLM_API_KEY` is present
- **THEN** the live `LLMService` implementation is injected and calls the configured provider on each new human message
